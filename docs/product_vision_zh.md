# MBC WalkWith 产品愿景

状态：草稿

本文档说明 MBC WalkWith 最终希望成为怎样的产品。路线图说明开发顺序；本文件说明主要功能闭环完成后，产品应该服务谁、解决什么问题、保持哪些边界。

## 一、产品定位

MBC WalkWith 是一个教会生活陪伴平台。

它的中心不是社交、流量或内容消费，而是帮助会友在日常生活中更稳定地：

- 阅读圣经。
- 听教会讲道。
- 理解经文与讲道之间的关系。
- 跟进教会公告、活动、周报和代祷。
- 管理奉献记录和年度奉献证明。

最终产品由四个部分组成：

- 移动 App：会友每天使用的入口。
- 后端 API 与任务系统：负责内容、权限、媒体、通知、奉献、代祷等可信数据。
- 后台管理系统：教会同工和管理员维护内容、审核发布、处理财务和查看审计记录的工作台。
- 公开官网：面向访客和新朋友展示教会宗旨、聚会信息、App 引导、地图和联系入口。

## 二、最终产品形态

完成后的产品应该给人安静、清楚、可信、实用的感觉。

会友打开 App 后，不应该被复杂信息打扰，而是可以自然地在几个核心场景之间移动：

1. 打开 App，继续上次读经。
2. 阅读当前章节，或使用文字转语音朗读圣经。
3. 选择经文做笔记、高亮、收藏，或查看读经辅助。
4. 查看与该段经文相关的讲道。
5. 听讲道，阅读讲道大纲、文稿和引用经文。
6. 从讲道引用返回圣经阅读。
7. 查看教会生活、公告、活动、小组、课程、服事、代祷和奉献信息。

后台同工的核心工作流程是：

1. 创建或导入教会内容。
2. 检查标题、时间、可见性、内容完整性和敏感性。
3. 必要时导入已复核的本地处理 package，或执行受控的后端维护动作。
4. 审核并发布内容。
5. 监控任务、通知、审计、代祷和奉献财务记录。

### 二阶段扩展形态

第一阶段完成后，产品继续扩展为教会日常运营平台，但移动 App 仍保持安静入口，不把后台工作台缩小搬进手机。

App 端继续保持四个主入口：

```text
Study     圣经阅读、TTS、笔记、相关讲道
Sermons   讲道、搜索、系列、经文关联、播放
Life      公告、活动、小组、课程、服事、代祷
Mine      我的资料、报名、服事、奉献、年度证明、通知设置
```

后台管理系统按六个工作区组织：

```text
Dashboard   待处理、系统健康、统计概览
Content     讲道、教会生活、圣经资料
Ministry    活动、小组、课程、服事排班、代祷
Giving      奉献、专项基金、对账、年度证明、退款争议
People      会员、关怀、权限
System      设置、通知、任务、审计
```

二阶段不是增加零散页面，而是补齐完整业务闭环：讲道发现、生活发布、活动签到、小组、课程、服事排班、专项基金、会员资料、牧养关怀、通知投递和后台数据看板。每个闭环都必须声明 source of truth、权限、审计和失败恢复路径。

### 三阶段成长主线

二阶段功能闭环完成后，下一阶段不再横向堆更多孤立模块，而是把已有读经、讲道、课程、小组、服事、关怀和通知串成教会门徒成长主线。

三阶段核心方向：

```text
新人进入教会
-> 被同工跟进
-> 分配成长路径
-> 参与读经计划、课程、小组和讲道讨论
-> 进入服事排班和同工训练
-> 成为能继续服事和带领他人的门徒
```

三阶段新增业务闭环：

- 门徒成长路径：编排阶段、任务引用、负责人和进度，不复制其他 feature 的数据。
- 新人跟进：管理新朋友资料、来源、分配、联系记录、邀请和转会员。
- 读经计划：让用户执行自己的每日读经计划，教会可提供推荐模板，App 使用本地经文文本完成阅读和 TTS。
- 讲道讨论包：把讲道延伸到小组讨论、生活应用、祷告方向和个人回应。

三阶段增强既有闭环：

- 小组管理升级为小组长工作台，但仍归 `group_ministry`。
- 服事排班升级为可用性、换班、替补、到岗和导出，但仍归 `serving_schedule`。

这一阶段的产品重心是“造就门徒、差派工人、领人归主”，不是增加社交互动或开放广场。

## 三、移动 App 目标功能

### 1. 读经 Study

读经是 App 的属灵中心。

目标功能：

- 圣经版本选择，使用公开版权或教会已获授权的经文文本。
- 书卷、章节、经文导航。
- 离线圣经阅读和本地缓存。
- 使用本地经文文本进行 TTS 朗读。
- 阅读进度、最近阅读章节和继续阅读。
- 经文笔记、高亮和收藏。
- 圣经搜索。
- 个人读经计划、每日读经任务和跨设备完成进度；教会内容只作为可选推荐模板。
- 人物、地点等读经辅助。
- 原文词汇提示，在资料允许的范围内提供帮助。
- 有来源标注的 AI/学习辅助解释。
- 按经文关联教会讲道和教导资源。
- 对困难或有争议的经文保持谨慎，必要时呈现主流解释范围。

边界：

- App 不应把未经审核、无来源的 AI 内容当作教会教义。
- 原始 AI 问答历史不应默认保存在本地。
- 公开圣经文本可以本地缓存；敏感个人学习资料应通过受控后端路径同步。

### 2. 讲道 Sermons

讲道模块不只是音频列表，而应该成为结构化的教会教导档案。

目标功能：

- 按日期、讲员、系列、主题、经文查看讲道。
- 搜索讲道标题、摘要、经文引用和文稿。
- 讲道详情页包含摘要、大纲、文稿、经文引用和音频。
- 音频播放支持速度控制、后台播放、锁屏信息和进度恢复。
- 播放进度本地保存，并可同步到后端。
- 从讲道引用一键跳回圣经阅读。
- 按经文、讲员、主题、系列推荐相关讲道。
- 讲道讨论包，包含小组问题、生活应用、祷告方向和行动回应。
- 对公开讲道元数据、文稿和常用内容做离线缓存。

后台和后端功能：

- 创建本地讲道草稿。
- 上传教会自录讲道音频。
- 上传或粘贴已预备好的讲道文案。
- 通过本地工作站完成转录、大纲和经文引用整理。
- 上传已复核的本地讲道 package。
- 保存审核备注和生成元数据。
- 生成内容必须经过管理员审核后才能发布。
- 归档或删除讲道时保留审计记录。

### 3. 教会生活 Life

生活模块应帮助会友更容易跟进教会生活，但不能变成信息流或社交平台。

目标功能：

- 以结构化卡片呈现周报，而不是只依赖 PDF。
- 发布公告、团契安排、服事机会和活动信息。
- 需要时提供活动详情和报名入口。
- 支持活动签到状态、二维码或签到码展示。
- 支持团契/小组可见性规则。
- 支持课程、课次、报名、资料和学习进度展示。
- 支持服事机会和我的服事提醒。
- 支持新人跟进入口、成长路径下一步、小组长工作台和讲道讨论材料。
- 支持通知权限入口；后台可保留周报、新讲道、代祷更新和未来活动提醒等投递偏好。
- 公开内容可给访客查看。
- 会友专属内容需要登录后查看。

后台和后端功能：

- 生活内容 CMS。
- 活动、签到和出席名单管理。
- 小组和团契资料、申请、成员和可见性管理。
- 课程、课次、资料、报名和出勤管理。
- 服事岗位、排班、确认、请假和通知管理。
- 支持草稿、审核、发布、取消发布和归档。
- 支持公开、会友、小组、私密等可见性。
- 支持活动时间、图片、行动按钮和未来附件。
- 内容修改保留审计记录。

### 4. 代祷 Prayer

代祷模块默认应以隐私和牧养谨慎为优先。

目标功能：

- 访客或会友可以提交代祷。
- 支持可见性选择：私密、会友、小组、公开。
- 清楚显示状态：待审核、已批准、隐藏、归档。
- 会友可以查看自己的请求。
- 已审核、适合分享的内容可在会友范围内展示。
- 广泛可见前需要牧者/管理员审核。

边界：

- 代祷请求应默认私密。
- 私密代祷内容不应随意缓存在设备上。
- 小组可见性必须依赖后端会员身份和权限判断。

### 5. 奉献 Giving

奉献是高敏感度功能，需要在安全、政策、财务和 App Store 要求都清楚后成熟推进。

目标功能：

- 奉献入口。
- 专项基金或奉献用途选择。
- 会友奉献历史。
- 年度奉献证明。
- 证明下载和导出。
- PDF 年度奉献证明，同时保留 CSV 作为兼容和财务导出。
- 年度证明可保存、打开和系统分享。
- 证明准备好时可通知或提示会友。

后台和后端要求：

- 使用确认过的支付服务商。
- 通过 Stripe Checkout 创建会友奉献支付会话。
- 验证过的 Stripe webhook 作为交易最终状态来源。
- 交易记录必须幂等，避免重复入账。
- 支持异步支付、退款事件。
- 跟踪 Stripe 手续费、净额、payout、退款和争议。
- 后台财务对账面板显示奉献总额、手续费、净额、退款、争议、payout 数、未对账和需复核记录。
- 财务操作需要权限控制和导出权限。
- 支持年度证明生成。
- 支持专项基金启停、目标金额、可见说明和财务统计。
- PDF 或文件资料应通过对象存储和签名访问控制。
- 财务流程需要审计记录。

边界：

- 交易不能只根据 App 端成功页面记录，必须以后端验证后的支付回调为准。
- 会友年度证明应显示奉献总额；手续费和净到账属于财务对账，不应从会友证明中扣除。
- 奉献数据应与普通 App 使用数据隔离。
- 奉献交易和年度证明 PDF 不应随意存在普通本地缓存中。

### 6. Mine 与会员账号

Mine 是身份和个人设置入口。

目标功能：

- 可选会友登录。
- 主题模式。
- App 语言和圣经版本行为。界面支持 English、Español、简体中文和繁體中文，首次进入默认跟随系统语言；圣经译本文本必须单独确认版权或 public-domain 来源。
- 读经辅助设置。
- 通知权限入口和通知中心，类别管理遵循系统原生通知设置。
- 团契/小组和会员资料展示。
- 我的活动报名、签到状态、课程、服事和关怀请求状态。
- 我的成长路径、读经计划进度和下一步提醒。
- 登出和设备通知 token 注销。
- 快捷进入系统通知权限、奉献历史、年度证明和关于信息。

## 四、后台管理目标功能

后台是教会同工和管理员的工作中心。

目标区域：

- 总览 Dashboard：内容、任务、代祷、奉献和系统健康。
- 讲道生产流程。
- 生活内容 CMS。
- 代祷审核。
- 活动报名和签到。
- 小组/团契管理。
- 课程/主日学管理。
- 服事排班。
- 会员关怀和探访跟进。
- 奉献和年度证明工作流。
- 专项基金和奉献用途管理。
- 会员管理。
- 后台用户和角色管理。
- 圣经知识资料管理。
- 历史任务诊断和系统健康检查。
- 系统设置。
- 审计日志查看。
- 数据看板和运营统计。

后台系统必须通过后端 API 工作，不应在浏览器端直接连接 Postgres、对象存储、支付平台或 AI 服务。

## 五、后端目标形态

在没有强烈运维理由前，后端应保持模块化单体架构。

核心职责：

- `/v1` REST JSON API。
- 统一响应和错误格式。
- 公开内容 API。
- 会员认证和会友专属 API。
- 管理员认证、角色权限和审计日志。
- Postgres 数据持久化和明确迁移。
- 历史任务诊断和系统健康。
- 讲道媒体存储和流式访问。
- 本地转录、大纲生成和经文引用 package 导入。
- 推送通知注册和发送。
- 设置和功能开关。
- 代祷、奉献等敏感流程。
- 活动签到、小组、课程、服事、关怀、专项基金和统计看板。

代码结构应保持当前模式：

- 内存 repository 用于开发和快速测试。
- Postgres repository 用于真实环境。
- Service 层协调业务规则。
- Route 层通过共享 contract 校验输入输出。

## 六、数据与离线策略

公开、低敏感度内容可以本地缓存：

- 圣经书卷、章节和经文文本。
- 公开讲道元数据、大纲、经文引用和文稿由 App 缓存和呈现。
- 公开生活内容。
- 阅读进度。
- 学习笔记、高亮、收藏，并为未来同步队列预留能力。

高敏感度数据应由后端控制：

- 私密或敏感代祷请求。
- 小组成员、课程名单、服事排班、关怀记录和探访备注。
- 奉献交易。
- 年度奉献证明 PDF。
- 支付平台状态。
- 后台和财务记录。
- 原始 AI 问答历史。

移动 App 应继续朝“公开内容本地优先”的体验前进；但权限、发布、审核和敏感数据必须以后端为准。

## 七、产品原则

- 圣经优先：读经和学习应是 App 的日常中心。
- 讲道连接圣经：讲道内容应自然指回经文。
- 可信胜过新奇：生成内容必须有来源、可审核、谨慎呈现。
- 教会生活不做社交噪音：生活内容应结构化、实用、容易浏览。
- 隐私默认优先：代祷和奉献必须有清楚权限边界。
- 牧养关怀谨慎：关怀记录、探访备注和小组成员关系必须按权限和审计处理。
- 发布前审核：生成内容、牧养敏感内容和财务内容都应经过审核。
- API 优先，离线友好：移动端通过 repository 使用数据，让 repository 屏蔽 mock、本地和远程来源差异。

## 八、非目标

本产品不应发展成：

- 通用社交网络。
- 以聊天为中心的 AI 神学 App。
- 在财务和政策边界未成熟前仓促上线的支付 App。
- 教会 PDF 文件堆放处。
- 只有移动端、没有后台审核和后端权威的数据系统。

## 九、第一阶段完成定义

当以下条件满足时，产品可以认为达到第一阶段完整形态：

- 会友可以阅读、朗读、标注和搜索圣经。
- 会友可以从经文自然进入相关讲道，也可以从讲道回到经文。
- 讲道可以创建、上传音频、处理、审核、发布、播放，并连接经文。
- 教会生活内容可以由后台发布，并在 App 中清楚展示。
- 代祷请求支持隐私、会员身份和管理员审核。
- 奉献历史和年度证明有权限控制和审计意识。
- 管理员可以管理内容、任务、会员、设置、代祷、奉献和审计。
- 公开内容具备离线友好体验。
- 敏感流程保持后端控制。

## 十、第二阶段完成定义

当以下条件满足时，产品可以认为达到第二阶段完整形态：

- 会友可以搜索讲道、按系列/讲员/经文浏览，并从讲道回到经文。
- 会友可以报名活动、查看报名状态，并在活动现场完成签到。
- 会友可以查看小组/团契资料，提交加入申请，查看自己所属的小组。
- 会友可以报名课程，查看课次、资料、出勤和学习进度。
- 会友可以查看自己的服事排班、确认服事、请假或申请换班。
- 会友可以选择奉献用途或专项基金，并在 Mine 中查看记录和年度证明。
- 会友可以提交代祷和关怀请求，查看自己可见范围内的状态。
- 同工可以在后台创建、审核、发布和归档活动、小组、课程、服事、代祷、关怀和专项基金。
- 财务同工可以查看专项基金、手续费、净额、退款、争议、payout、年度证明和对账状态。
- 管理员可以通过 Dashboard 查看待处理事项、系统健康、任务失败、内容状态和聚合运营数据。
- 所有高风险动作具备后端权限判断、结构化错误和审计记录。

## 十一、上线前重点

当前产品主干已经基本完成，下一阶段重点不是继续堆功能，而是上线生产化：

- 生产服务器部署。
- 域名和 HTTPS。
- Stripe 生产 webhook。
- Apple Developer 和 Google Play 开发者账号。
- 对象存储和签名下载。
- 隐私政策、使用条款和年度证明正式文案。
- 真机测试。
- App Store 和 Google Play 发布资料。

MBC WalkWith 的目标是成为教会可以长期维护、会友愿意日常使用、同工可以实际操作的数字基础设施。
